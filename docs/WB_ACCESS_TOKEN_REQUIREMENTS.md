# Требования к токену Wildberries для WB Insight

Актуально для текущего продукта WB Insight и действующей модели WB API.

## До регистрации WB Insight в Каталоге решений Wildberries

Используется **Базовый токен (Base token)**.

Продавец создаёт отдельный токен именно для WB Insight и выбирает уровень доступа **Только чтение**.

Обязательные категории:

- Контент;
- Аналитика;
- Цены и скидки;
- Статистика;
- Продвижение;
- Финансы.

Эти категории соответствуют текущим production-контурам продукта: карточки товаров, остатки/воронка/хранение, цены, заказы/продажи, реклама и финансовый отчёт.

## После регистрации в Каталоге решений

Используется **Сервисный токен (Service token)**, созданный продавцом именно для WB Insight.

Backend должен иметь обе серверные настройки:

- `WB_SERVICE_ID` — ID/asid сервиса;
- `WB_SERVICE_SECRET` — сервисный секрет Wildberries.

Для каждого запроса с Service token backend передаёт:

- `Authorization: Bearer <seller-token>`;
- `X-Client-Secret: <WB_SERVICE_SECRET>`.

Поле `for` в JWT должно иметь вид `asid:<WB_SERVICE_ID>`. Токен другого сервиса отклоняется.

## Что WB Insight не принимает

- **Personal token** — его запрещено передавать облачному стороннему сервису;
- **Test token** — он предназначен только для sandbox;
- токен без одной из обязательных категорий;
- токен с доступом Read/Write вместо «Только чтение»;
- истёкший токен;
- отозванный или неактивный токен;
- Service token другого авторизованного сервиса.

## Проверка при подключении

Backend:

1. декодирует JWT локально;
2. определяет тип по `acc`;
3. читает реальный срок действия из `exp`;
4. проверяет продавца `sid` и, для Service token, `for=asid:<id>`;
5. проверяет битовую маску категорий `s`;
6. требует бит `30` («Только чтение»);
7. выполняет live-проверку `GET https://common-api.wildberries.ru/ping`;
8. только после успешной проверки шифрует и сохраняет токен.

JWT-декодирование используется только для чтения документированных claims и не считается доказательством того, что токен не был отозван. Live `/ping` закрывает эту проверку перед сохранением.

## Жизненный цикл

WB API токены действуют до 180 дней, но WB Insight не вычисляет срок самостоятельно. Источником истины является `exp` в JWT.

Сервисный секрет также имеет собственный жизненный цикл Wildberries и должен храниться только на backend как production secret. Он никогда не передаётся во frontend и не сохраняется в пользовательских настройках.
