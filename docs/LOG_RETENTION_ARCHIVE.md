# Архивирование неизменяемых журналов

P126 добавляет безопасный эксплуатационный контур архивирования для двух append-only источников:

- `audit_events` — аудит безопасности и значимых бизнес-действий;
- `operation_log_events` — техническая сквозная диагностика P122–P125.

Инструмент предназначен для подготовки проверяемой архивной копии перед утверждённым оператором жизненным циклом хранения. Он **не удаляет записи из PostgreSQL** и не ослабляет существующие DB-триггеры, запрещающие `UPDATE`/`DELETE`.

## Почему удаление не автоматизировано

Сроки хранения зависят от утверждённой юридической и эксплуатационной политики. Репозиторий не должен сам назначать срок, после которого доказательства аудита можно уничтожить.

До утверждения такой политики безопасное поведение только одно:

1. выбрать дату отсечения вручную;
2. экспортировать записи старше неё;
3. проверить целостность архива;
4. перенести архив и манифест в защищённое off-host хранилище;
5. не удалять исходные строки автоматически.

Поэтому P126 закрывает **техническую готовность к архивированию**, но не подменяет юридическое решение о сроке хранения.

## Команда

Инструмент находится в `ops/archive_logs.py`.

Он читает параметры подключения из стандартных переменных:

- `DB_HOST`;
- `DB_PORT`;
- `DB_NAME`;
- `DB_USER`;
- `DB_PASSWORD`.

Пароль не принимается параметром командной строки и не попадает в манифест.

Пример:

```bash
cd /home/projects/wb
source backend/venv/bin/activate

python3 ops/archive_logs.py \
  --before '2026-01-01T00:00:00+00:00' \
  --output-dir /var/backups/wb/log-archive
```

Дата отсечения обязательна и должна содержать часовой пояс. Архивируются только записи, у которых `created_at < cutoff`.

Можно выбрать один источник:

```bash
python3 ops/archive_logs.py \
  --before '2026-01-01T00:00:00+00:00' \
  --kind audit \
  --output-dir /var/backups/wb/log-archive
```

Допустимые значения `--kind`:

- `all`;
- `audit`;
- `operations`.

## Формат

Для каждого источника создаётся отдельный `jsonl.gz`.

Каждая строка — один JSON-объект исходной записи. UUID и временные значения сериализуются в строковый формат, денежные `Decimal` — без перехода через `float`.

Дополнительно создаётся манифест вида:

`log-archive-YYYYMMDDTHHMMSSZ.manifest.json`

Он содержит:

- версию схемы;
- UTC-время создания;
- точную дату отсечения;
- имя исходной таблицы;
- число экспортированных строк;
- первую и последнюю дату в файле;
- размер файла;
- SHA-256;
- явный признак `deletion_performed=false`.

DB hostname, пользователь, пароль и строка подключения в манифест не записываются.

## Атомарность и права файлов

Архив сначала пишется во временный файл `.partial`, проверяется чтением, а затем атомарно переименовывается.

Файлы создаются с правами `0600`, каталог приводится к `0700`, насколько это позволяет файловая система.

Если операция не завершилась, временный файл не считается архивом. При ошибке текущего запуска созданные им файлы удаляются.

## Проверка без PostgreSQL

Существующий архив можно проверить повторно:

```bash
python3 ops/archive_logs.py \
  --verify-manifest /var/backups/wb/log-archive/log-archive-20261020T120000Z.manifest.json
```

Проверяются:

- структура манифеста;
- наличие каждого файла;
- SHA-256;
- корректность gzip/JSONL;
- число строк;
- наличие `created_at`;
- отсутствие записей на или после даты отсечения.

Самопроверка инструмента без БД:

```bash
python3 ops/archive_logs.py --self-test
```

Она также выполняется в `Release integrity`.

## Эксплуатационный процесс

Перед архивированием:

1. убедиться, что дата отсечения утверждена действующей политикой;
2. проверить свободное место;
3. создать обычный резервный снимок PostgreSQL по текущему backup-процессу;
4. выполнить архивирование;
5. повторно проверить манифест;
6. скопировать файлы и манифест в зашифрованное off-host/object storage;
7. проверить контрольные суммы уже на целевом хранилище.

Сам факт локального архива не является off-host backup.

## Политика удаления

В P126 **нет команды purge**.

Это намеренное fail-closed ограничение. Append-only триггеры `audit_events` и `operation_log_events` не изменяются. Обычный пользователь приложения не получает специального обхода запрета `DELETE`.

Если после юридического согласования потребуется уменьшать hot-объём PostgreSQL, это должно быть отдельным изменением с:

- утверждённым сроком хранения;
- подтверждённой архивной копией;
- отдельными полномочиями оператора БД;
- проверкой восстановления;
- аудитом самой операции;
- защитой от удаления ещё не архивированных данных.

## Release gate

До stable остаются обязательными два внешних подтверждения:

- владелец/юрист утверждает фактические сроки хранения и удаления;
- оператор подтверждает off-host хранение и восстановимость архивов.

P126 предоставляет воспроизводимый механизм экспорта и проверки, но не объявляет эти внешние решения выполненными.
