# Фильтры операционной диагностики

P123 расширяет сквозную диагностику P122 серверными комбинируемыми фильтрами. Цель — быстро перейти от общего журнала к конкретной цепочке пользователя, кабинета Wildberries, платежа, тарифа, фоновой задачи или технической ошибки.

## Что можно фильтровать

Администратор с правом `diagnostics:read` может одновременно задать:

- пользователя: email, ФИО, UUID, телефон или ИНН;
- токен/кабинет маркетплейса: UUID, метку подключения или внешний ID кабинета;
- платеж: внутренний UUID или ID платежного провайдера;
- тариф: UUID, код или название;
- задачу синхронизации: UUID либо сущность синхронизации;
- `operation_id` и `request_id`;
- подсистему, операцию, компонент и тип события;
- статус, важность и направление события;
- внешнего провайдера;
- один или несколько HTTP-кодов либо группу `2xx`, `3xx`, `4xx`, `5xx`;
- код ошибки;
- минимальную длительность операции;
- временной диапазон;
- только события, требующие внимания;
- только незавершённые операции;
- только повторные попытки.

Фильтры объединяются через логическое «И». Например, можно выбрать одного пользователя, его кабинет Wildberries, подсистему `sync`, период за последние сутки и режим «Только требует внимания».

## Разрешение пользовательских сущностей

Текстовые фильтры сначала переводятся в внутренние идентификаторы. В ответ API возвращается поле `resolved`, чтобы администратор видел, какие пользователи, токены, платежи, задачи или тарифы фактически попали в выборку.

Для фильтра токена система связывает не только события, где токен является непосредственным субъектом, но и операции фоновых `sync_job`, созданных для этого токена. Это позволяет смотреть цепочку синхронизации кабинета, а не только вызовы внешнего API.

Фильтр тарифа показывает события пользователей, связанных с найденным тарифом, и платежные операции этого тарифа. Историческая принадлежность пользователя тарифу определяется существующими записями подписок и платежей.

## Быстрые представления

В Control Panel доступны предустановки:

- «Требует внимания»;
- «Ошибки платежей»;
- «Проблемы WB»;
- «401 / 403»;
- «429»;
- «5xx»;
- «Медленнее 5 сек.»;
- «Незавершённые»;
- «Повторные попытки».

Предустановка заполняет обычные фильтры и запускает тот же серверный запрос. После этого администратор может уточнить выборку дополнительными полями.

## Поиск и фильтры

Быстрый поиск P122 остаётся отдельным инструментом для случая, когда известен только один идентификатор. Найденную сущность можно кнопкой «Показать журнал» перенести в соответствующий фильтр:

- пользователь → фильтр пользователя;
- кабинет → фильтр токена;
- платеж → фильтр платежа;
- sync job → фильтр задачи;
- тариф → фильтр тарифа.

После фильтрации любую строку журнала можно раскрыть и перейти к полной связанной операции или ко всему HTTP-запросу по `operation_id` / `request_id`.

## Производительность и безопасность

Фильтрация выполняется на backend до пагинации. Браузер не загружает весь операционный журнал для локального поиска. На странице можно запросить 50, 100, 200 или 500 событий.

P123 не меняет правила безопасности P122. Секреты, токены, Authorization/cookies, JWT, API-ключи, реквизиты карты, CVV/CVC, платежные secrets и URL платежной формы не становятся доступными через новые фильтры. Ответ дополнительно проходит общий `sanitize_operation_data`.
