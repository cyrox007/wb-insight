## Что подтверждено кодом

P115–P118 имеют регрессионные/acceptance-проверки и были слиты после зелёного exact-head CI соответствующих pull request.

Текущая почтовая приёмка проверяет возможности адаптера (`transactional`, readiness verification/recovery) и реальную доставку, а не бренд провайдера.

Текущий systemd-updater готовит кандидата до изменения рабочей версии, создаёт точку восстановления БД, блокирует параллельное обновление и выполняет согласованный откат.

## Дополнительное hardening после аудита

P122–P125 добавили сквозную диагностику и центр операционных инцидентов. P126 добавляет проверяемый read-only архив для `audit_events` и `operation_log_events` без обхода append-only защиты.

Фактический срок хранения и допустимость удаления журналов не назначаются кодом и остаются отдельным внешним решением владельца/юриста.

## Что нельзя считать закрытым кодом

### Защита веток

Проверка GitHub API 15 октября 2026 года показала:

- `dev`: `protected=false`;
- repository rulesets: отсутствуют;
- административный branch-protection endpoint недоступен используемой GitHub App.

Следовательно, зелёный CI сам по себе пока не запрещает обход процесса через прямую запись в ветку. До stable требуется административно включить защиту `dev` и `main`, затем повторно проверить фактические правила.

### Production-like acceptance

Необходимо выполнить на **точном выпускаемом SHA**:

- upgrade существующей PostgreSQL;
- реальный WB seller account и полный sync;
- сверку финансовых метрик;
- реальную email verification/password reset доставку;
- backup/restore drill;
- desktop/mobile browser smoke;
- клиентский onboarding от регистрации до первой аналитики;
- применимые проверки эквайринга.

Артефакты более старого SHA не переносятся на новый release candidate.

## Правило завершения аудита

Аудит можно считать полностью закрытым только после двух внешних подтверждений:

1. `dev` и `main` фактически защищены правилами GitHub;
2. production-like acceptance завершён на том же Git SHA, который повышается до стабильной версии.
