# Точки входа в операционную диагностику

P127 продолжает P122–P125 и делает переход к расследованию частью рабочих административных сценариев.

## Платежи

В разделе **«Платежи → Журнал оплат»** у каждой строки доступна ссылка **«Диагностика»**. Она открывает `/control-panel/diagnostics` с фильтром `payment_query=<payment_id>`.

Такая же ссылка **«Открыть в диагностике»** находится в раскрытой карточке платежа. Администратор сразу попадает в связанную операционную цепочку: создание попытки, запрос к провайдеру, ответы, callback, изменение состояния платежа и активацию подписки — если соответствующие шаги записаны сквозной диагностикой.

## Пользователи, тарифы и кабинеты

Существующие точки входа P124 сохраняются:

- карточка пользователя → `user_query=<user_id>`;
- карточка тарифа → `tariff_query=<tariff_id>`;
- кабинет маркетплейса → `token_query=<token_id>`.

## URL-контракт

Точки входа используют только несекретные идентификаторы и общий URL-контракт фильтров P123/P124. Ссылку можно сохранить или передать другому сотруднику, у которого есть `diagnostics:read`.

В URL запрещено помещать сырой токен Wildberries, JWT, `Authorization`, cookies, пароль, API-ключ, PAN/CVV/CVC и секреты платёжного провайдера.

Наличие ссылки не обходит RBAC: диагностические API по-прежнему требуют `diagnostics:read` на backend.
