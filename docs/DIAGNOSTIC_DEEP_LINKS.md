# Глубокие ссылки операционной диагностики

P124 связывает рабочие экраны Control Panel с серверными фильтрами P123. Диагностику можно открыть уже с выбранной сущностью, а состояние фильтров хранится в query-параметрах маршрута `/control-panel/diagnostics`.

## Поддерживаемые параметры

Диагностическая страница принимает те же параметры, что серверный журнал P123, в том числе:

- `user_query` — пользователь;
- `token_query` — кабинет/токен маркетплейса;
- `payment_query` — платёж;
- `tariff_query` — тариф;
- `job_query` — задача синхронизации;
- `operation_id` и `request_id`;
- технические фильтры: подсистема, провайдер, статус, HTTP-коды, период и другие параметры P123.

После открытия страницы поля фильтров заполняются из URL автоматически и журнал сразу загружается. При ручном изменении фильтров URL обновляется через `router.replace`, поэтому текущую диагностическую выборку можно сохранить в закладку или передать другому администратору с теми же правами.

## Контекстные переходы

В Control Panel добавлены контекстные переходы:

- из карточки пользователя — «Диагностика пользователя» с `user_query=<user_id>`;
- из карточки тарифа — «Диагностика тарифа» с `tariff_query=<tariff_id>`;
- в результатах сквозного поиска P122/P123 — «Показать журнал» для найденной сущности;
- в контексте пользователя на странице диагностики — «Журнал пользователя»;
- для каждого кабинета маркетплейса — «Журнал кабинета» с `token_query=<token_id>`;
- для текущего тарифа пользователя — «Показать журнал тарифа».

Платежи, фоновые задачи и другие сущности по-прежнему можно открыть прямой ссылкой через соответствующий query-параметр или из результата сквозного поиска. Следующие рабочие экраны могут использовать тот же URL-контракт без нового backend API.

## Пагинация

`offset` также сохраняется в URL. При переходах «Назад» и «Дальше» диагностическая страница сохраняет фильтры и меняет только смещение выборки.

## Безопасность

Глубокая ссылка содержит только несекретные идентификаторы и условия фильтрации. Сырые токены Wildberries, JWT, Authorization/cookies, пароли, API-ключи и реквизиты платежей в URL не помещаются.

Доступ к странице и данным по-прежнему контролируется backend-правом `diagnostics:read`; наличие ссылки само по себе не даёт дополнительных прав.
